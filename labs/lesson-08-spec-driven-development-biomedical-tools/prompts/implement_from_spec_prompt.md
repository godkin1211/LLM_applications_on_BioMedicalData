# Prompt: Implement from SPEC.md

Read `SPEC.md` before editing code.

Implement the smallest version that satisfies the acceptance criteria.

Rules:

- Do not add features outside the spec.
- Do not edit files outside the allowed list in `tasks.md` or the user prompt.
- If the spec is ambiguous, stop and ask before coding.
- Write tests or validation fixtures before claiming completion.
- Preserve user changes.
- Report any deviation from the spec.

Validation:

- Run the commands listed in `SPEC.md`.
- Report command, exit status, and key output.
- If validation fails twice, stop and summarize the blocker.

Final report:

- files changed
- tasks completed
- validation commands run
- acceptance criteria status
- deviations from spec
- remaining risks
